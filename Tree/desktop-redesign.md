# 桌面端重设计：图 → 拆解 → 实现

流程是三步，每步都有可核对的东西：

1. **图** — `docs/concepts/v2/01~06.jpg`，六张概念图（doubao-seedream-5.0-pro 生成，`manifest.json` 有清单）；
2. **拆解** — 本文档的拆解表：每张图有哪些区块、什么组件、放什么数据；
3. **实现** — `desktop/renderer/{index.html,style.css,app.js}`，实际界面截图在 `docs/screenshots/v2/`。

**看图的注意事项**：图里所有文字都是模型编的英文占位（Orders / Acme / $128.5K），
中文一律是糊的。所以图只用来定 **版式骨架和视觉基调**，字段和数据一律以真实
CLI 输出为准。这也是为什么文档里每条都写"实现落点"——真源是代码和令牌。

## 二、逐图拆解

### 01 概览 → `pageOverview`

| 区块 | 组件 | 数据 |
|---|---|---|
| 侧栏 | 品牌（方块 logo + 主标题 + 副标题）、6 项导航、底部设置 + 用户块 | 静态 / `status.db` |
| 顶栏 | 面包屑（房子图标 › 段 › 段）+ 右侧 4 个描边胶囊 | `status`、`models` |
| KPI ×4 | 大号青色数字 + 灰色标签 | 公司/岗位/已打分/负面证据 |
| 主表 | 卡标题带 ⓘ、"最近一次"、表头独立底色条、9 列、圆形等级徽章 | `data.companies[]` |
| 表脚 | `显示 1–N 条，共 M 条` + 分页 | 前端切片 |
| 右栏 | TOP5 榜单（**排名徽章 #1~#5** + 名称 + 条形 + 值）+ 底部链接 | `data.jobs[].fit` |

**关键决定**：派遣列用紧凑文字（疑似/否/未知）而不是胶囊——图上每行都是小徽章，
胶囊会把行撑高，20 行全是圆角块很吵。

### 02 公司详情 → `pageCompanyDetail`

| 区块 | 组件 | 数据 |
|---|---|---|
| 头部 | 渐变方块（公司首字）+ 名称 + 元信息行 + 右侧大分数 `/100` + **实心等级方块** + 派遣胶囊 | `name/basic/score/labor_dispatch` |
| 行 1 左 | 五维雷达（同心五边形 + 顶点 + **标签下方带百分比**） | `score.dimensions` |
| 行 1 右 | 工商信息（12 项 kv）+ 在招岗位（标题 + 城市·经验 + 薪资标签） | `basic.*`、`jobs[]` |
| 行 2 左 | 维度明细：4-5 条圆头条形 + 数值 | `score.dimensions` |
| 行 2 右 | 风险：计数行 / 空态 | `risk.counts` |
| 行 3 | 评价：**情感圆点 + 标题 + 摘要 + 来源·时间** | `reviews{src:[]}` |

### 03 技能词云 → `pageSkills`

| 区块 | 组件 | 数据 |
|---|---|---|
| 主卡 | 标题 + ⓘ + 右侧"按频次"按钮 | — |
| 云体 | **螺旋布局的绝对定位词**，字号 11–57px，远景词更暗 | `cloud.skills[]` |
| 卡脚 | 分隔线 + 三个图标胶囊（全部/技术栈/其他标签，选中态实心青）+ 右侧"共 N 次提及" | `cloud.counts` |
| 右栏 | TOP10：名称 + 条形 + **百分比** + 底部说明 | 同上 |

**实现要点**：容器宽度要渲染后才知道，所以 `paint()` 先量 `clientWidth` 再排布；
早期按固定 1100px 算导致词重叠（截图对比过）。布局用螺旋 + 矩形碰撞，西文按 0.64em、
中文按 1.02em 估宽。

### 04 岗位 → `pageJobs`

| 区块 | 组件 | 数据 |
|---|---|---|
| 筛选卡 | 关键词 + 城市 + 4 个下拉 + 页数 + 公司数 + 主按钮 | `filters.fields` |
| 开关行 | 平台复选 + 三个开关 + 停止按钮 | `filters.toggles` |
| 列表卡 | 6 列 + 圆形等级 + 分页脚 | `data.jobs[]` |

### 05 岗位详情 → `pageJobDetail`

| 区块 | 组件 | 数据 |
|---|---|---|
| 头部 | 大标题 + 胶囊行 + 右侧适配度 + 等级方块 | `title/salary/city/fit` |
| 左卡 | **规格行**（大写小标签 + 右对齐值 + 分隔线）×5 + 描边技能标签 + JD 灰段落 | `experience/…/description` |
| 右卡 1 | 公司摘要：小 logo + 名称 + 评分 + 等级 + 派遣 | `company.*` |
| 右卡 2 | 来源：来源 / 链接（带外链图标）+ 两个按钮 | `source.*` |
| 右卡 3 | 适配度明细：**颜色随分数变化**的条形（≥80 绿 / ≥70 青 / ≥60 琥珀 / <60 红） | `fit.dimensions` |

### 06 对话口 → 全局抽屉

| 块 | 组件 |
|---|---|
| 悬浮球 | 圆形、青色描边 + 光晕、未读红点 |
| 抽屉 | 从侧栏右边起、占屏高 42%、顶部 1px 边框 + 投影 |
| 消息 | **左侧系统（描边）/ 右侧用户（青色实心）**，每条上方"谁 · HH:MM" |
| 输入 | 输入框 + 发送按钮；问答按顺序逐题追问，答完自动提交 |

## 四、与图不同的地方（有意为之）

| 图 | 实现 | 原因 |
|---|---|---|
| 英文占位文案 | 真实中文数据 | 图里文字不可用 |
| 0–10 分制 | 0–100 分制 | 后端评分就是百分制 |
| 对话在页面内 | 底部抽屉 | 工作台要能边看表边运行，抽屉不挤占布局 |
| 侧栏 12 项 | 6 项 | 只有六个页面 |
| KPI 带"↑8.2%" | 只有数字 | 没有历史对比数据，不编趋势 |

## 五、待办

1. 表格分页目前是单页占位（54 条一次给完），公司多了要真正切片
2. 词云容器 resize 会重排，但拖动窗口时仍可能短暂重叠（180ms 防抖）
3. 岗位详情右栏三卡在窄屏会掉到底部（媒体查询 1240px）
